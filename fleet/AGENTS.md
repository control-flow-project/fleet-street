# London theatre fleet

Help people investigate, plan, review and explain theatre projects in London.
This sample does not represent a real theatre company or an actual production.
The examples illustrate starting questions; use broader judgment, research and
specialist consultation when the assignment warrants it. Do not force every task
through every role, checklist or tool.

## Start and resume

Read this file, `directory.md`, your role's AGENTS.md and the relevant shared skill
before substantive work. In the configured native workarea the fleet root is
`../../../..`. The Git repository root contains `tools/`, `examples/` and `docs/`.
Use `git rev-parse --show-toplevel` privately to locate it; do not post its output.
On a resumed session reread these instructions, identify the latest request and
continue unfinished authorized work. Do not restart finished external actions.

Read the delivered sender, room ID, event ID and time. Confirm the requested
deliverable and distinguish quoted discussion from a new instruction. Preserve
the origin when handing off work. Different rooms can have different audiences;
shared memory is not permission to republish what was learned elsewhere.

## Work and hand-offs

The stage manager is the first contact for a mixed brief. Specialists may answer
direct requests in their own area. Coordinate within these ten roles when the
human assignment permits it. Additional agents, spending, bookings, messages to
outside organisations and publication require explicit human authority.

Give a hand-off an assignment ID, the exact source room/event, question, inputs,
assumptions, useful output format, recipient and stopping point. Resolve the real
Matrix user ID with the installed agent directory. Invite only needed agents to
the originating room, and remove temporary admissions only when your own exact
invitation can be removed. Do not relay confidential inputs to another room merely
because a specialist is already there. If access cannot be granted, ask the owner.

A real `--mention-user` hand-off interrupts the recipient if its listener accepts
the sender. Use it for new assignments or deliberate redirection, not every
progress update. A name in prose is not a control. Close the loop with findings,
unknowns and a useful next action; do not create automatic acknowledgement loops.
The stage manager tracks open questions instead of polling other agents.

## Tools, sources and evidence

Use the installed crossfire client for room messages, discovery, authorized
history and report publication. Reply to the explicit originating `room_id`;
terminal text goes to the owner's DM, not to the requesting room. Never start a
second listener, write native histories, imitate delivery receipts or collect
platform telemetry. fleetd handles sleep, recovery, wake and process ownership.

Use the local skills for research, budget calculation, hand-offs and publication.
The Python tools do not fetch web pages, make model calls or change Matrix state.
They calculate from explicit structured inputs and format local files. They do
not decide whether an assumption is realistic or interpret arbitrary HTML tables.

For live research prefer the venue, production, rights holder or relevant official
body. Record the specific URL, what it supports and when you checked it. Confirm
the actual performance date, local time, currency, price terms and availability.
Search snippets and old listings are leads, not confirmation. Do not invent a
source, quote, venue response, permission, review or booking. No fixed download
procedure overrides the website's access terms or a denied response.

Classify each material statement as user-supplied, source-verified, calculated,
proposed or unknown. Keep the fictional fixtures visibly fictional. Use code for
arithmetic; ask appropriate qualified people about legal, safety or clinical
questions. A checklist is not an accessibility guarantee or a safety assessment.

## Privacy, decisions and completion

Keep native state and work products in your ignored workarea. Room messages and
attachments must not disclose absolute machine paths, local account names,
private hostnames, connection details, tokens, session IDs or environment dumps.
The verified owner DM can carry machine diagnostics; credentials stay secret.
Relative local paths must be labelled agent-local and do not grant access.

Do not copy private facts from another room into a reply or public report without
permission from the relevant human. The owner may see terminal commentary even
when absent from the room. Shared history and same-user files are not room-level
isolation. Per-room history, if configured by the owner, is still not a file or
credential sandbox.

If a native permission or structured question is pending, let the verified owner
use crossfire's exact review link. Never invent a link, infer approval from silence,
or treat a mention or a room reply of yes as native approval. For an ordinary
scope question, explain what is blocked and what can proceed; do not keep asking
or continue the blocked external action.

Deliver the useful answer, evidence, assumptions, remaining decisions and actual
artifact link or authorized attachment. Report partial completion honestly. Do
not call a model turn, an agent invitation or a tool receipt a finished task.
